# Native workspace storage

Session 4 added the Rust domain library; session 5 connects it to the [isolated desktop preview](../desktop/README.md). It is not wired to a production data directory. All verification uses disposable file-backed SQLite databases.

## Layers

- `contracts.rs`: typed command/query enums, transaction port, injected clock/UUID provider. There is no raw-SQL or renderer-supplied file-path command.
- `model.rs`, `validation.rs`, `ordering.rs`: serializable domain records, validation and fractional ordering. The default-alphabet ordering implementation is a CC0 port of the web dependency, checked against 240 generated cases.
- `commands.rs`, `queries.rs`: transactional business operations and indexed reads. Multi-entity operations remain inside one native transaction.
- `sqlite.rs`: connection factory, versioned schema setup, transaction ownership and typed record mapping. `SqliteWorkspace::open` accepts a trusted absolute path and a `Runtime`; `SystemRuntime` supplies production timestamps and UUIDs.

Records are stored as canonical typed JSON with **stored generated columns** for ownership, lifecycle, ordering and lookup fields. Generated projections cannot drift from their JSON source. Foreign keys, partial unique indexes and triggers enforce relationships and ordering; normalized name keys are maintained by the writer. This retains portable DTOs without sacrificing indexed board, child, history and archive reads. JSON and SQL stay inside the native adapter.

Each successful command increments the persistent workspace revision in the same `BEGIN IMMEDIATE` transaction. The reply is constructed before commit but returned only after commit succeeds. Optional expected workspace revision and field/generation checks fail within that transaction. Queries read the version and data in one read transaction. The caller must serialize access to the owning service; SQLite also enforces a bounded two-second lock wait across connections.

Wire responses contain a typed version and serialized domain `value`. Missing records and void command results use JSON `null`; the desktop TypeScript bridge maps those to the existing optional/void contracts and validates the expected DTO for each operation. The host publishes notifications only after commit.

The connection enables foreign keys, WAL and FULL synchronous durability. Schema version 2 adds a serializable draft journal to the dedicated application ID. Unsupported databases, including session-4 schema 1, are rejected without initializing over their contents; protected migration remains session 6. The session-5 preview passed a forced-process-exit drill, but power-loss and installer durability remain unproven.

`drafts.rs` defines the draft contract and SQLite adapter. Staging acknowledges only journal durability. Commit checks the stored token, expected original text and generation, then saves canonical data, increments revision and removes the token in one transaction. Failed writes leave the recovery record intact. Recovery reads never apply text automatically.

Historical event column IDs intentionally have no foreign key. Archived records may reference a missing column, but active records may not. Restoring into a replacement column appends after its existing items. Child tasks cannot be independently archived or restored. Global entity UUID collisions are rejected.

Name matching uses Unicode lowercase, not SQLite's ASCII-only `NOCASE`. ECMAScript whitespace trimming, UTF-16 text limits and UTF-16 tag sorting are explicit. Fixtures include accents, Greek final sigma, dotted I, BOM/NEL whitespace and astral/BMP ordering. Locale-specific casing beyond the current web host's locale needs an explicit migration policy before supporting other locales; the tests do not establish universal Unicode-version/locale equivalence.

## Local verification

From the repository root in PowerShell:

```powershell
. ./native/Use-WorkspaceToolchain.ps1
cargo fmt --manifest-path native/workspace/Cargo.toml --check
cargo test --locked --offline --manifest-path native/workspace/Cargo.toml
cargo clippy --locked --offline --manifest-path native/workspace/Cargo.toml --all-targets -- -D warnings
cargo run --locked --offline --manifest-path native/workspace/Cargo.toml --example basic
```

The toolchain script uses the previously approved `D:\KanbanBuildTools` cache and a separate `targets/kanban-workspace` output directory. The runnable [composition example](examples/basic.rs) creates and removes its own temporary database; it never opens the user's workspace.

The checked-in fixture is generated by `src/repositories/nativeParity.test.ts` against the actual Dexie adapter, then consumed by native tests. It covers all 16 commands and 19 queries, including rejection cases. Only private Dexie index fields are omitted; domain IDs, revisions, timestamps, return values, ordering and histories are compared. Test clocks/UUID streams are deterministic and are injected rather than used by production.

Normal `npm test` checks that the oracle still matches the fixture. To deliberately regenerate after reviewing a contract change:

```powershell
$env:WRITE_NATIVE_FIXTURES='1'
npm run test -- src/repositories/nativeParity.test.ts
Remove-Item Env:WRITE_NATIVE_FIXTURES
```

Never regenerate merely to accept an unexplained mismatch. The Windows native CI job runs formatting, tests and Clippy; web CI separately checks fixture consistency. Hosted CI results require a push and are not implied by local passes.

Sessions 5–7 add the Tauri bridge, durable journals, verified snapshots/recovery and portable migration. `ManagedWorkspace` controls preview tickets, safety snapshots and replacement; `PortableStorage` exports canonical data and import receipts. Portable validation and transactional persistence live in separate modules. The [portable composition example](examples/portable.rs) imports only the bundled synthetic fixture into temporary storage:

```powershell
cargo run --locked --offline --manifest-path native/workspace/Cargo.toml --example portable
```

`portableParity.test.ts` produces the browser fixture; Rust imports/reopens/exports it and can emit `portable-native.json` with `WRITE_NATIVE_FIXTURES=1`. Frontend tests import that native fixture back into Dexie. Do not regenerate either fixture to hide semantic differences. See [session 7](../../docs/desktop/SESSION_07.md) for current evidence and the remaining release gates.
